# 备用机场 USB 出口设计

## 目标与边界

为 MihomoSurgeBridge 增加“代理出口网络”：默认“系统自动”；用户也可选择一个 macOS USB 网络服务作为优先出口。所选服务可用时，Mihomo 的远端代理连接使用它；不可用时，Mihomo 不绑定出口接口，使用系统默认网络。USB 恢复后自动重新绑定。工具不修改系统路由、Surge 配置或 Surge 直连规则。本地 SOCKS5 仍只监听 `127.0.0.1`。

当前应用只有经本地 SOCKS5 的“测试代理连通性”，没有节点健康检查或批量测速界面。本功能使 Mihomo 发起的代理连接及以后由 Mihomo 发起的节点测试遵循同一出口设置；不新增测速功能。订阅下载仍遵循系统网络。

## 已选方案与取舍

采用 Mihomo 全局 `interface-name`。它覆盖 Mihomo 的出口连接，配置集中，并符合 [Mihomo 出口接口文档](https://wiki.metacubex.one/en/config/general/)。网络切换时重新生成并重启 Mihomo，允许已有连接短暂中断。逐节点绑定会增加更新和回退的一致性成本；修改系统路由会影响其他应用，均不采用。

## 设置与兼容

- 设置页增加“代理出口网络”选择：“系统自动”和“优先指定 USB 网络”。后者要求从检测到的 USB 网络服务中选一个，展示服务名称与当前网卡名；界面不预设 `en5`。
- 保存网络服务 ID，而不是服务名称或 BSD 网卡名。每次检查都通过当前 macOS 网络配置把服务 ID 解析成实际网卡名。USB 服务列表依据系统网络服务与对应硬件的 USB 连接关系生成，避免仅靠名称包含“USB”判断；停用或暂时断开的已配置 USB 服务仍可展示并标注状态，以便重新连接。
- 旧版 JSON 配置缺少新字段时解码为“系统自动”，不提高现有 schema 版本。导入、导出的 `.msbridge` 不携带设备专属服务 ID；导入后使用“系统自动”。
- “系统自动”不生成 `interface-name`，保持现有 Mihomo 配置和行为。选中 USB 但不可用时同样移除该字段。

## 可用性与回退原因

将检测与决策封装为单一网络状态快照，至少包含所选服务、解析后的接口、可用性、回退原因，以及系统当前默认出口的可显示名称。

依次检查：服务仍存在且启用；接口仍存在并处于活动状态；接口有可用的 IPv4 或 IPv6 地址（排除仅回环和链路本地地址）；接口存在到外网的作用域路由；通过限定该接口的短超时外网连接探测。探测至少使用两个固定的公网地址，任一成功即可通过，避免 DNS 或单一探测目标导致错误回退。探测只验证该接口对外建立连接的能力，不宣称任何具体 SSR 节点可用。各失败阶段分别显示“服务未找到”“服务已停用”“USB 未取得可用 IP”“USB 无外网路由”或“USB 无法访问外网”。如果 macOS 因“需要时启用”停用了服务，将显示停用回退，并提示在系统网络设置中关闭该选项。Apple 的 [USB 网络说明](https://support.apple.com/en-gb/guide/mac-help/mchl7594e36f/mac)列出了相应设置。

回退目标是系统默认网络，而非写死 Wi-Fi；只有系统默认出口确认为 Wi-Fi 时才显示“回退到 Wi-Fi”。若系统默认网络也不可用，界面应如实显示“系统默认网络不可用”，不声称回退成功。

## 运行时更新

- 启动 Mihomo 前先完成一次出口决策，生成与当前出口一致的运行配置。
- 监听网络配置和路径变化，并以低频定时复查弥补漏掉的事件；合并短时间重复通知。联网探测异步执行，不阻塞界面。设置或网络状态在探测过程中变化时，丢弃过期结果。
- 只有实际出口接口从某个 BSD 名称变为另一个名称，或在绑定与系统自动间切换时，才更新运行配置。单纯 IP 或状态文案变化不重启 Mihomo。
- 从当前节点与端口生成候选 Mihomo YAML；先校验候选配置，再原子写入运行配置并通过现有进程管理器重启。切换失败时恢复上一份有效配置并尝试恢复进程，界面和日志显示失败，不把“期望出口”误报为“当前出口”。网络事件不重写 Surge 输出文件。
- 设置保存、订阅更新和网络切换共用同一串行协调流程，避免旧探测结果或并发重启覆盖新配置。退出时取消监测任务。

## 界面状态

设置页展示所选 USB 服务、解析出的当前网卡、当前 Mihomo 出口，以及回退原因。Mihomo 未运行时用“下次启动将使用…”描述决策；运行时仅根据已成功应用的配置显示“当前出口”。切换和失败时显示明确状态。概览中的代理连通性测试继续经 `127.0.0.1` SOCKS5 执行，因 Mihomo 的全局出口设置而遵循当前出口。

## 验证

- 自动模式及旧配置：生成 YAML 不包含 `interface-name`，旧设置可加载，Surge 输出不变化。
- USB 可用：使用所选服务当前 BSD 名称生成 `interface-name`；网卡名变化后重新解析，不沿用旧名称。
- 停用、拔线、无 IP、无作用域路由、探测失败：生成无接口绑定的配置，状态显示对应原因；恢复后重新绑定。
- 运行中切换：仅在出口变化时重启，失败时恢复有效配置；本地 SOCKS5 地址不变。
- 在实际 Wi-Fi 与 USB 同时联网的 Mac 上，分别验证 USB、断开回退和重连恢复，并通过外部网络观测确认代理连接出口。当前受限执行环境无法读取本机网络服务，因此硬件验证需在可访问两条网络的环境完成。
