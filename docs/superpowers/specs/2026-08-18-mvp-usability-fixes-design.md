# Mihomo 状态与 MVP 易用性修复设计

## 目标

修复配置检查后 Mihomo 状态卡住的问题，并按实测反馈调整诊断动作、订阅标记、Surge 策略组名称、端口输入框和版本信息。保持 MVP 范围，不新增节点选择器、批量测速或其他诊断功能。

## 1. 配置检查与进程状态

“检查配置”执行 Mihomo 的 `-t -f <生成配置>`，只检查应用生成的 YAML 是否能被当前 Mihomo 解析。它不检查节点网络质量，不启动、停止或重启正在运行的 Mihomo。

`MihomoProcessState` 只描述真实进程生命周期。配置检查不再把它改成“正在检查配置”，检查期间改用 `AppModel.isBusy` 和 `statusMessage` 显示进度并禁用相关按钮。无论检查成功还是失败，原有 Mihomo 进程状态都不受影响。

成功提示明确为“Mihomo 生成配置检查通过”；失败继续显示脱敏后的 Mihomo 校验输出。

## 2. 代理连通性测试

概览按钮改为“测试代理连通性”。测试仍选取当前第一个可用节点，通过本地 Mihomo SOCKS5 监听、该节点的认证路由和外部 HTTP 204 地址完成一次端到端访问。

该动作验证的是本地监听、用户认证、路由到 SSR 节点及节点外网访问的组合结果，不代表全部节点可用。界面不增加节点选择或全量测试；成功提示保留实际使用的节点名称。

## 3. 订阅自动更新标记

订阅名称旁的单独小时钟改为带图标的“每小时”文字标记，只在该订阅启用自动更新时出现，并提供悬停说明“此订阅每小时自动更新”。不开启自动更新时不显示标记。

## 4. Surge 输出名称

只调整生成的 Surge 策略组显示名称：

- “全部 SSR”改为“全部节点”。
- 地区策略组从“地区名 + SSR”改为地区名本身。
- 每个订阅对应的策略组继续使用订阅名称。
- 重名继续使用现有 `#2`、`#3` 后缀去重。

现有 `all-ssr.conf`、订阅和地区文件名保持不变，避免无必要的文件迁移和遗留文件清理问题。

## 5. 设置与诊断布局

SOCKS5 端口使用独立标签和至少 180 点宽的输入框，输入内容采用等宽数字，确保五位端口完整可见。

设置页最底部显示应用名称、短版本号与构建号，例如 `MihomoSurgeBridge 0.1.2（构建 3）`。版本信息从应用包 `Info.plist` 读取；开发运行环境缺少字段时显示“开发版本”。

## 6. 版本与验证

应用版本升级为 `0.1.2`，构建号升级为 `3`。

验证范围：

- 配置检查期间和完成后，正在运行的 Mihomo 状态保持“运行中”。
- 配置检查失败不会把仍在运行的进程标记为停止或异常。
- 代理测试按钮和状态文案符合实际语义。
- 生成器测试覆盖“全部节点”和无 `SSR` 后缀的地区组名称。
- 端口输入框和版本信息能够正常构建与显示。
- 现有自检、Release 构建、应用签名和 ZIP 解压验签继续通过。

## 范围边界

本次不修改订阅解析、SSR 节点路由、端口选择规则、定时更新频率、输出文件名、菜单栏/Dock 行为或 Mihomo 进程所有权规则。
